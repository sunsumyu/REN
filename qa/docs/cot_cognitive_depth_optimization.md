# Think CoT 数据质量升级方案：认知深度（Cognitive Depth）卡控与动态场景泛化

## 1. 痛点分析：为何产生低价值“单跳问题”？
在目前的合成数据管线中，出现了类似“咳喘顺丸的医保类型是什么？”这类纯事实检索类问题。这些问题对提升大模型的 Think CoT（思维链）推理能力**几乎毫无价值**。导致该问题的原因有两个核心架构盲点：

1. **大模型的惰性生成（Lazy Generation）**：当生成器只接收单一实体或简单知识图谱属性作为输入时，大模型会本能选择“阻力最小”的生成路径，将图谱属性直接转化为“xxx属性是什么”的单维查询题，而逃避构建复杂的因果链条。
2. **评估网关的质检盲区**：我们现有的质检体系（如事实忠实度、精确度等）侧重于评估大模型**解答（Answer）的正确性**。对于“单跳事实题”，由于其答案绝对忠实于参考资料，往往能轻易骗过裁判模型获得高分，导致低智问题成功入库。

---

## 2. 破局之道：企业级生成与卡控策略

为了彻底根除低价值问题，确保每一条入库数据都能激发大模型进行复杂的机制推断、多步条件判断与冲突消解，我们决定采取 **“动态泛化约束（生成端） + 推演复杂度红线（裁判端）”** 的双轨优化方案。

### 2.1 生成端：基于 Evol-Instruct 思想的动态场景泛化
不写死任何具体的药物或场景，而是采用**动态元规则倒逼（Meta-Rule Constraints）**。
在 `QUESTION_CREATOR` 的核心 Prompt 中加入强制性机制，迫使模型每次在生成问题时，必须基于上下文提取出的特征，动态“捏造”复杂的临床病例。

**动态泛化引擎规则设定：**
生成的场景必须随机组合以下至少一种干扰/约束条件：
- **人群冲突**：合并特殊生理期（如孕产妇）、极端年龄或基础肝肾功能衰竭。
- **合并用药**：引入存在潜在药代动力学（PK）或药效学（PD）相互作用的虚构/已有用药史。
- **合规与政策**：结合处方药管理、医保限制或超出说明书用药（Off-label use）的临床权衡。

通过这种方式，遇到“阿司匹林”会自动生成“围手术期停药与心血管风险双重冲突”场景；遇到“咳喘顺丸”会自动生成“慢支合并糖尿病的医保自费限制”场景，实现完美的领域泛化。

### 2.2 裁判端：引入第 9 维评估指标（推演复杂度 `complexity`）
在原有评估网关基础上，增加一个专门针对“认知深度（Cognitive Depth）”的一票否决考核项。

**考核标准：3步逻辑推演底线**
- **直接拦截（不及格，<6分）**：任何只需一步查阅（“查字典”）即可解答的单跳问题，即使答案100%正确，也予以严厉扣分拦截。
- **高分入库条件**：问题本身必须具有认知难度，解答过程必须展现出“信息提取 ➡️ 条件冲突验证 ➡️ 综合评估决策”至少 3 步以上的清晰逻辑推演链。

## 3. 具体实施路径规划

### Phase 1: 升级生成器 Prompt (prompts.py)
重构 `_BOOTSTRAP_QUESTION_CREATOR_TEMPLATE`，加入以下核心法则：
> “**【推理性要求】严禁生成可以直接查找原文回答的单跳问题（如：医保类型是什么、规格是多少）。你必须基于知识点构建多条件冲突或复杂的临床情境，确保回答该问题至少需要 3 步以上的逻辑推演（例如：病史信息提取 -> 匹配禁忌机制 -> 评估政策风险及替代方案）。**”

### Phase 2: 升级裁判模型 Schema (eval_models.py)
扩展 `ComprehensiveJudgeMetrics` Pydantic 模型，新增 `complexity` 字段：
```python
complexity: JudgeMetric = Field(
    description="推演复杂度评分。评估问题本身的认知深度及对应回答是否展现了真实的逻辑推演链。若问题属单跳查询（仅需查阅无推演）直接给予严重扣分（不及格）；涉及多条件冲突消解与深度诊断可给高分。"
)
```

### Phase 3: 全局管线适配 (main.py & run_evals.py)
1. **替换卡控阈值**：将 `main.py` 和自动化评测脚本中的算分除数和卡控数组扩充为 9 维。
2. **终端日志增强**：向控制台与审计文件中输出实时的“推演复杂度”打分明细。
3. **主提示词升级**：更新 `JUDGE_COMPREHENSIVE_PROMPT`，使大模型裁判熟练掌握新的第 9 维评判刻度。
