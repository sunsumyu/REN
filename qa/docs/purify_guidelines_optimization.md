# 🩺 医疗多轮问答 CoT（思维链）数据净化准则企业级升级方案

在以大语言模型（LLM）为底座构建医疗垂直领域推理模型（如 DeepSeek-R1 类 reasoning model，或临床决策支持系统 CDSS 智能体）时，`<think>` 标签内思维链（Chain of Thought, CoT）的质量是决定模型是否具备 **“深度临床因果推理能力”** 和 **“高抗幻觉鲁棒性”** 的生命线。

本报告对当前项目中 `llm_purify_dataset.py` 中定义的清洗净化准则（`PURIFY_SYSTEM_PROMPT`）与审查裁判准则（`JUDGE_SYSTEM_PROMPT`）进行深度、系统性的合理性评估，指出其在生产级/企业级微调训练中的潜在局限，并提供一套**开箱即用、完全重构的“企业级”提示词方案**。

## 🎯 核心诊断：当前净化准则是否合理？是“企业级”吗？

### 1. 净化方向的“合理性”评估 (Reasonableness Review)

当前制定的清洗净化准则（`PURIFY_SYSTEM_PROMPT`）在整体思路上是**高度合理且完全正确的**：
*   **物理隔离工程废话（合理）**：移除非医学推理的模板（如“根据某个切面回答”）、JSON格式构建词（如“现在构建JSON”）、以及免责声明。大模型如果用含有这些噪声的思维链进行 SFT/DPO 微调，会在推理阶段产生严重的 **“格式幻觉”**（例如，在正常的医生与患者对话中，模型的思考甚至回答部分会突然蹦出 `step_id: P1`、`注意不要输出 markdown` 等工程描述）。
*   **清除检索废话（合理）**：清除“检索文档 3 是关于二甲双胍的，可以忽略”等由于 RAG 管线检索噪声带来的纠结。
*   **强力恢复极端无推理样本（合理）**：对于 100% 都是垃圾工程词汇的样本进行零重构，防止模型学到“唯唯诺诺的零信息量复读”。

     `"证据"`, `"循证"`, `"排除"`, `"无关"`, `"忽略"`, `"临床指南"`, `"药理关联"`, `"机制"`, `"诊断"`, `"自我修正"`。

2. 🩺 【维度二：医学事实严谨度 (medical_rigor_score - 0到100分)】
   - **判定逻辑**：评估净化后的思维链是否完整保留了原问题与原始素材中核心的“医学事实与硬数据”。
   - **硬指标核验**：检查发生率（如‘5.9%’）、受试样本量（如‘7537名’）、特定剂量（如‘500 mg’）、特定分子靶点与受体（如‘DPP-4’、‘依托孕烯’）、核心毒性名词（如‘乳酸酸中毒’）是否发生丢失或曲解。

3. 🧠 【维度三：逻辑深度与思维熵 (logical_depth_score - 0到100分)】

## 📈 三、工程算力成本与吞吐量预警 (Compute & Latency Cost Control)

当我们将思维链从 100-200 字的短陈述升级为 500-1000 字的高熵 4 阶段深度推理长文时，**单次调用的 Token 生成量上升了 4~5 倍**。大规模跑批几十万条数据时，会面临极大的成本与延迟压力。在工程架构上，建议采用以下三套组合拳进行降本增效：

### 1. 物理启用 API 端“提示词缓存 (Prompt/Context Caching)”
*   **原理解析**：
    由于我们的 `PURIFY_SYSTEM_PROMPT`（约 1500 tokens）和 `JUDGE_SYSTEM_PROMPT`（约 1200 tokens）属于高频重复调用的超长系统级提示词，如果每次 API 请求都重新计算这部分 Token，会导致高达 80% 的输入成本被浪费。
*   **最佳实践**：
    主流大模型提供商（如 Google Gemini API、Claude API、DeepSeek API）均支持 **Prompt Caching**。使用该技术，对于命中缓存的系统提示词，**输入成本可直接降低 70% 至 90%**，同时首字延迟（TTFT）大幅缩短。在代码配置中，应确保 system prompt 的静态结构完整稳定，避免频繁渲染动态随机数据进入 system prompt 以防缓存失效。

### 2. 梯级模型分流机制 (Tiered Model Routing)
*   **企业级降本原则**：
    **裁判（Judge）用贵模型，清洗（Purifier）用快模型**。
*   **实施方案**：
    - **清洗提纯（第一阶段）**：使用推理成本极低、生成吞吐量极高但上下文遵从度极强的模型（如 **Gemini 1.5 Flash** 或 **GPT-4o-mini**）进行跑批。其强大的长文本遵循能力完全能够完美融入 4 阶段逻辑，且费用只有 Premium 模型的 10% 左右。
    - **质检质控（第二阶段）**：在 Judge LLM 质检关口（Quality Gate），则必须调用旗舰级模型（如 **Gemini 1.5 Pro** 或 **GPT-4o / Claude 3.5 Sonnet**），用最严苛的逻辑审计能力对 Flash 模型生成的结果进行打分把关。如果得分不达标（如 < 85分），再启动“退避重试”，重试时可考虑升级为 Premium 级模型进行精细化净化。这样可以节省约 **75% 的整体算力资源**。

### 3. 异步并发控制与弹性限流 (Rate Limiting & Async Semaphore)
*   **代码级保障**：
    在大规模并发调用时，防止触发云厂商的 TPM (Tokens Per Minute) 或 RPM (Requests Per Minute) 限流阻断。在 `llm_purify_dataset.py` 中，应通过信号量进行全局物理节流：
    ```python
    # 限制全局最大并发请求数为 10，防范速率过载并保持高吞吐
    semaphore = asyncio.Semaphore(10)
    
    async def purified_with_retry(item):
        async with semaphore:
            # 执行 API 调用逻辑
            ...
    ```
